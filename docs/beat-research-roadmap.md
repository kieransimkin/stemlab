# Multi-evidence beat finding, counting and audio–motion synchronization roadmap

Status: research-backed implementation roadmap, 23 October 2026.

## Architectural decision

**StemLab owns beat evidence, per-detector comparisons and audio inference;
DanceRudiments owns exact type/channel/pip semantics and playback; PrismMoves
owns rendered-visual reports through PixelCue.** No component copies another
component's engine. Each extractor exports a tagged, bounded, source-hashed
evidence stream; a separate comparison layer may compare, reject or request
review. A predicted beat-grid point, measured spectral peak, detected foot
strike, model-inferred downbeat and user-confirmed musical beat are different
types of evidence, even if their timestamps coincide.

Preserve the existing StemLab detector/source majority-vote consensus as-is
until controlled benchmarks justify a separately versioned alternative. Detect
and record cross-detector dependencies: BeatTransformer checkpoints, multiple
separator drum stems, and decoders sharing the *same* neural activation are not
independent votes. Independence belongs to underlying model/feature families,
not the number of rows generated by an inference job.

## Candidate methods and integration choices

| Family | Candidate | Status, strengths and cautions |
| --- | --- | --- |
| Existing model | [Beat This!](https://github.com/CPJKU/beat_this) | Already present: direct beat/downbeat peaks without DBN, broad genre coverage. Keep original model output. Code and published weights MIT, but source dataset rights still need evaluation |
| Existing model | [BeatNet](https://github.com/mjhydri/BeatNet) | Already present: joint beat/downbeat/meter route, particle/DBN variants. Retain exact decoder and checkpoint provenance |
| Existing model | [Beat Transformer](https://github.com/zhaojw1998/Beat-Transformer) | Already present: demixed multi-instrument context and distinct source evidence. Spleeter-trained checkpoint may differ with present separators; benchmark domain shift |
| Existing/optional | [All-In-One](https://github.com/mir-aidj/all-in-one) / [all-in-one-infer](https://github.com/openmirlab/all-in-one-infer) | Already in StemLab structure pipeline: tempo, beat positions, downbeats, bar positions, sections. Do not relabel it as an independent percussion-only source; inspect package provenance and model versions |
| New classical (implemented) | [librosa DP/PLP concepts](https://librosa.org/doc/main/api/generated/librosa.beat.beat_track.html) | ACF, comb periodicity, onset intervals, local PLP and peak-path DP supplied by StemLab comparison layer; no checkpoint/download needed |
| Planned classical | [Essentia RhythmExtractor2013](https://essentia.upf.edu/tutorial_rhythm_beatdetection.html) | `multifeature` and `degara` provide separate classical baselines; frame-level source and output tempo confidence. **AGPLv3/commercial licensing requires isolation and review** |
| Planned classical | [aubio](https://aubio.readthedocs.io/en/latest/) | Causal and streaming onset/tempo baseline; lightweight browser/realtime prospect. Validate Python/Windows packaging |
| Planned classical | [madmom-infer](https://github.com/openmirlab/madmom-infer) | Modern NumPy implementation with RNN/DBN beat, CRF, non-HMM decoders, ACF/comb tempo and downbeat processors. Sharing activations with an existing model must count as one correlated upstream source |
| Planned model | [1D-StateSpace](https://github.com/mjhydri/1D-StateSpace) | Joint beat/downbeat/meter/tempo causal decoding. Useful as an alternative postprocessor, *not* independent if it consumes BeatNet activations |
| Investigate | [BeatFM](https://github.com/zaiisao/BeatFM) | Experimental research code; MusicFM dependency, checkpoint availability, dataset rights, large weight/storage and pinned runtime need further audit |
| Investigate | [MotionBeat](https://arxiv.org/abs/2510.13244) | Embodied contrastive and foot-contact-aware representation. Evaluate whether usable released weights and inference scripts exist; paper alone is not an installable backend |
| Motion classical | [kinematic minima and synergies](https://pmc.ncbi.nlm.nih.gov/articles/PMC12046673/) | Distinguish control-space velocity minima, acceleration spikes, PCA/TD-PCA activation minima, and true world-space joint/foot contact events |
| Visual | PrismMoves/PixelCue optical flow and silhouette change | Optional evidence when no rig exists; render/camera movement and effects may spuriously appear as dancer motion. Do not confuse with actual motion tracks |

The model catalogue is **not** an instruction to download any model or to move
weights from an existing installation. Models remain optional, separately
versioned and downloaded only with explicit permission under project-local
`models/`, with checkpoint hashes, licences and reproducible runtime receipts.

## Deliverable stages and gates

### Stage A — source-conserving classical baseline (implemented in candidate patch)

- Stable `stemlab.rhythm-evidence.v1` and `rhythm-comparison.v1` documents.
- Five classical tempo/pulse decoders; a separate DP chain that retains only
  onset-supported events and ordinal gaps; 8 s local tempo-window proposals.
- Audio band onset features, 64-pip rudiment velocity/turning features,
  timestamped rig control/kinetic-pause features and verified package-derived
  accent features; imported model JSON retains provenance.
- Half/double BPM and 3/4/5/6/7 accent-cycle hypotheses, without claiming
  downbeat/meter correctness. Uncalibrated score and explicit abstentions.
- Explicit cross-source offset gate and immutable input/source hashes.

Test gates: generated click/kinetic fixtures, silent input, half/double
ambiguity, changing tempo, model import, source integrity, source clock and
output nonclobbering. Run `ruff`, pytest, package check, multi-Python CI.

### Stage B — direct model-adapter expansion

Add optionally installed Essentia, aubio and madmom-infer routes *behind a
capability registry*. Reuse existing official StemLab BeatThis/BeatNet/
BeatTransformer/All-In-One runners instead of launching duplicate ones.
Provide every backend with `model_family`, model/checkpoint SHA-256,
input provenance, resampling delay, acoustic feature lineage, CPU/GPU costs,
license, failures and skipped reasons. Install no research checkpoint from CI.

Test gates: independently checked fixture stamps and saved-reference artefacts,
known failure modes, source-hash mismatches, clean offline `--no-model-downloads`
execution. Record exact upstream licence/runtime restrictions.

### Stage C — stronger variable tempo, counting and meter

Replace global extrapolated fixed-grid assumptions with multiple competing
*piecewise tempo trajectories* derived by tempogram Viterbi/DBN/particle filter
and dynamic programming. Keep half/double, triplet and compound-meter
interpretations separate rather than forcing 4/4. Report beat indices even
across missed detections, with observed/inferred source labels, source-frame
integer anchors, uncertainty intervals and per-regime drift. Infer bars only
with supporting downbeat/meter evidence or user approval. Preserve all original
model detections read-only in `stemlab.beat-timeline.v1` and store corrections
in separate revisions. No hidden fabricated timestamps.

Test gates: 70→160 BPM ramps, ritardando, abrupt jumps, syncopated UK garage,
triplet shuffle, 3/4, 4/4, 6/8, 5/4, 7/8, swing, tempo-doubling and silent
breaks. Compare at multiple metrical levels and first-anchored error guards.

### Stage D — rig/world-space beat and contact inference

Build in DanceRudiments a *read-only offline world-space keypoint evaluator*
from its exact numbered rig profile, rest transforms and hierarchy (not a
replacement native sampler). Extract foot-plant/toe-off, ankle local minima,
COM height troughs, velocity extrema, turning accelerations and contact-slip
probability. Separate global root translation from dance gestures; ignore
quaternion sign jumps and discrete rig selectors. Compare scalar controls,
world-space group energy, PCA/TD-PCA synergy, kinetic minima and full
contact-based motion beats as alternative families. Detect simple gait phase,
left/right lead and repeated phrase lengths, but do not label motion pulses as
music downbeats by default.

Test gates: static reference T-pose, calibrated Kandi Boom source transform,
sequential rig chunk seams, alternating q/-q, large root drift, sliding feet,
arm crossings, retargeted hips/feet, mirrored movement, 30/60/120 fps timing,
missing channels and non-Rigify source rigs. Real salsa/ballet validation
requires licensed local assets and actual Blender/WebGL visual QA.

### Stage E — multi-stream synchronization and consensus candidates

Join motion and audio sources only with **verified source identity and explicit
clock mapping**. Estimate candidate lag via cross-correlation, event matching
or dynamic time warping, but do not apply it without review. Preserve direct
clock mappings and extracted source audio frames. Compare confidence and
independent-model agreement over bars and tempo regimes. Show a ranked
consensus candidate with `support_by_independent_family`, not a hidden vote.
Expose a phase picker and manual bar-one/meter confirmation in StemLab/DanceMoves;
show per-detector evidence lanes in Kandi Boom's gallery without changing
native transport. Until alignment is accepted, simply show disagreeing lanes.

Test gates: known ± offset, multiple plausible pulse phases, stem latency,
partial clips, motion in half/double speed, missing onsets, variable tempos
and no matching groove. Never report a synchrony metric without actual overlap.

### Stage F — objective evaluation and reproducible benchmark harness

Construct curated, rights-reviewed train/validation/test partitions; frozen
source hashes, beat/downbeat and motion-contact *human reference* anchors;
no test-time choice of source-specific thresholds. Use `mir_eval` F-measure
(±70 ms), Cemgil, CMLc/CMLt/AMLc/AMLt, P-score and information gain; downbeat
and bar-level metrics, tempo family accuracy, phase MAE, interval drift and
abstention/calibration curves separately. Test wall-clock, peak RAM, GPU VRAM,
model-download/cache costs and licence constraints. Evaluate results on
synthetic clicks, licensed real dance clips and licensed music, including
out-of-distribution and no-beat/no-motion cases.

Acceptance needs a documented **ablation**: compare single-stream DSP, each
neural model, each new independent motion stream, and fused candidate results.
Do not claim an improvement because a visual example looks smoother or because
multiple related models agree. A final release must pass the corresponding
GitHub release/registry/browser gate against the exact immutable commit.
